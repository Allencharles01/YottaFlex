**Your four answers are applied:** the three actor types plus `planner_party_id`, one ground-truth anomaly row per shipment, excursion runs that continue across gaps, and readings from a non-assigned device treated as untrusted.

**Key design rule:** the schemas check structure only. Rules that injected anomalies break on purpose (custody continuity, device overlap, declared-policy match) are left to the engine and the Phase 6 validation, so anomalous but well-formed data still loads. Tests show that a deleted custody event and a reading from another device both pass their schemas.

**Drift guards:**
- `test_data_dictionary.py` fails if the dictionary and the schemas disagree on tables, fields, order, types, required flags, layer or primary key.
- `test_er_diagram.py` checks that every table, column and FK is in the diagram, and that each line follows the erDiagram syntax.
