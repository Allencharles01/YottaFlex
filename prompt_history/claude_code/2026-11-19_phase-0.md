## Phase Summary

**What was built:** the plan saved word for word (checked with `cmp`), a decisions log, `CLAUDE.md`, the packaging files, the config, and the core `coldchain` package: config loading, custom errors, ID builders, enums, seeded random streams and a CLI with one `version` command. I also ran `git init` (branch `main`).

**Design decisions** (all logged in `docs/DECISIONS.md`):
1. **Device vs Logger:** a Device is a physical logger with calibration data, reused across shipments. A Logger is one device assigned to one shipment.
2. **Version in one place:** the build tool is hatchling, and it reads the package version from `__version__`.
3. **Random streams keyed by stage name:** each stage's stream comes from `SeedSequence(seed, spawn_key=(crc32(stage),))` instead of the order of `.spawn()` calls. Adding or reordering stages can never shift another stage's numbers. A test pins the actual values.
4. **Strict config checks:**
   - Unknown keys are rejected, which catches YAML typos.
   - Every scale, scenario and issue type must be present.
   - Scenario weights must sum to 1.
   - Each injection rate must be between 0 and 1, and their total at most 1.
   - The date and trip-duration ranges must be in order.
   - Errors name the file and the field.

**Deviation from the plan:** I added `tests/test_enums.py`. The plan only listed tests for config, ids and rng, but it also asks for tests on every module.

**Known limitations:**
