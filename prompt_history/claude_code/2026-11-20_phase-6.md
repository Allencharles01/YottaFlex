## Phase Summary

**What was built**
- **`coldchain validate`** runs 133 checks in two tiers (your choice at the start of the phase).
  - **Integrity checks** must always pass; any failure exits 1. They cover keys, foreign keys (batched DuckDB joins), enums, schema, duplicates, date order, lifecycle, consistency, and arithmetic reconciliation. The reconciliation recomputes lot quantities, `dwell_min`, excursions, coverage and gaps from the raw readings, without using the engine.
  - **Business-rule checks** catch the defects the injected anomalies create on purpose. They are reported but don't fail `validate`.
  - `--source baseline` judges the clean pre-injection snapshot. It never reads `ground_truth/`, proven by a code scan plus a run with `ground_truth/` deleted.
- **`coldchain evaluate`** reports:
  - precision/recall/F1 per issue type and per reason code;
  - a status confusion matrix;
  - the excursion-duration exact-match rate;
  - accuracy per scenario;
  - each finding matched to the anomaly that explains it.

  It exits 1 on any unexplained finding at every scale, and on any metric below 100 % at starter. It also refuses a validation summary whose input files changed since it was written.
- **What counts as a detection:** the issue type's signature fires on the engine output, *and* the shipment's status, reason codes and excursion durations exactly match the anomaly's expected values. All definitions are in `docs/evaluation.md`.
- **BACKLOG #3 (security):**
