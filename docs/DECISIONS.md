# Decisions Log

Every project decision is recorded here: date, decision, reason.

| # | Date | Decision | Reason |
|---|------|----------|--------|
| 1 | 2026-11-19 | **Device vs Logger split.** *Device* (`DEV-000001`) is a physical logger: 1,000 of them, reused across shipments, holding calibration data. *Logger* (`LOG-<shipment-id>-01`) is the assignment of one device to one shipment (one row per shipment, 1:1 with Shipment). A device may never have two assignments with overlapping time windows, except where an anomaly is deliberately injected. | The brief asks for 1,000 loggers but 5,000 shipments, and uses the shipment-scoped ID `LOG-<shipment-id>-01`. Splitting the physical device from its assignment resolves the contradiction and keeps both the brief's ID format and its volumes. |
| 2 | 2026-11-19 | Build backend: **hatchling**, `src/` layout, package version kept in `src/coldchain/__init__.py` (`__version__`) and read dynamically by `pyproject.toml`. | One source of truth for the version (DRY); hatchling is the standard, light-weight PEP 517 backend. |
| 3 | 2026-11-19 | RNG streams: a child `SeedSequence` is derived per stage from `SeedSequence(seed, spawn_key=(crc32(stage_name),))`, rather than relying on the order of `.spawn()` calls. | Using a stable hash of the stage name means adding, removing or reordering stages never changes another stage's random numbers. This is equivalent to `spawn()` (which also sets `spawn_key`) but keyed by name instead of call order. |
| 4 | 2026-11-19 | Config validation: pydantic v2 models with `extra="forbid"`; scenario weights must sum to 1.0 (±1e-6); each injection rate is in [0, 1] and their sum is ≤ 1 (injections target disjoint shipments); `date_window.end > start`; `trip_duration_hours.max ≥ min`. Errors are re-raised as `ConfigError` with the file path and field location. | Fail fast with clear messages (principle 1: error handling). Forbidding unknown keys catches typos in YAML. |
| 5 | 2026-11-19 | Removed the root copy `YottaFlex_Master_Prompt.md`; `docs/PROJECT_PLAN.md` is the official plan. | User instruction at Phase 0 approval; avoids two copies of the plan drifting apart. |
| 6 | 2026-11-19 | **Phase 2 TODO:** the `generate` command must accept a `--config <path>` option (default `config/default.yaml`) so a custom config file can be passed. | User instruction at Phase 0 approval; `load_config(path)` already supports it. |
| 7 | 2026-11-19 | **Actors as parties.** `party_type` gains PLANNER, LOGISTICS_ANALYST and OPERATIONS_MANAGER; `shipments` gains `planner_party_id` (who set `declared_policy_id`). Status-event actors: PLANNED → planner, PICKED_UP/IN_TRANSIT → carrier, AT_STOP → the stop's party, DELIVERED → receiver, UNDER_REVIEW → logistics analyst, RELEASED/QUARANTINED → operations manager. | User choice at Phase 1. Every actor in the brief then appears as data, and every status event has a real actor. |
| 8 | 2026-11-19 | **Ground-truth anomalies: one row per affected shipment.** `anomalies` PK = (`anomaly_id`, `shipment_id`); the two-shipment case has two rows sharing an `anomaly_id`, each with its own expected status, reasons and durations. Added `removed_record_ids` (deleted IDs) next to `affected_record_ids` (existing IDs). | User choice at Phase 1. Per-shipment rows make precision/recall per shipment straightforward; splitting removed vs existing IDs keeps the "affected IDs exist" check valid for deletions. |
| 9 | 2026-11-19 | **Excursion runs are not broken by gaps.** A run of same-direction out-of-range readings continues across missing readings, so its duration (`last − first + interval`) includes the missing time. The gap itself is still judged separately (DATA_GAP). | User choice at Phase 1. Conservative: missing data during an excursion is assumed to be out of range. |
| 10 | 2026-11-19 | **Readings from a non-assigned device are untrusted.** They add LOGGER_NOT_ASSIGNED and are excluded from gap, coverage and excursion calculations. With no logger assignment at all, the window falls back to actual departure → arrival with zero trusted readings. | User choice at Phase 1. Such readings cannot be attributed to the assigned, calibrated device. |
| 11 | 2026-11-19 | **Schemas enforce structural rules only.** Format, dtype, nulls, enums, keys, row-level consistency and parent IDs embedded in child IDs live in `schemas.py`. Business rules that anomalies break on purpose (custody continuity, device overlap, declared-policy match, gaps, FK integrity, lifecycle) are left to the engine (Phase 4) and the validation suite (Phase 6). Every rule in the data dictionary is tagged S / V / E. | Otherwise anomalous but well-formed raw data would be rejected at load time, and anomalies must surface as explained findings instead. |
| 12 | 2026-11-19 | **Effective windows are half-open** `[effective_from, effective_to)`, with dates read as UTC midnight and a null `effective_to` open-ended. REFRIG_2_8 V1 ends 2026-07-01 and V2 starts 2026-07-01. Within a code, versions must not overlap and must increase with `effective_from` (checked in both the schema and the reference loader, via the single helper `schemas.overlapping_policy_versions`). | Half-open windows leave no gap and no overlap at the boundary instant. |
| 13 | 2026-11-19 | **Physical types.** Timestamps: `datetime64[us, UTC]` (pandas 3 default resolution), whole minutes. Dates: `datetime.date`. Nullable integers: `Int64`. Strings: pandas `str`. Multi-valued cells: `\|`-joined, reason codes in `ReasonCode` declaration order (most severe first). Tables are strict (no extra columns) and column-ordered. | One fixed physical representation keeps the output deterministic; strict schemas also stop label columns leaking into raw tables. |
| 14 | 2026-11-19 | **Gap and coverage formulas.** `expected = window / i + 1`; `coverage_pct = round(100 × trusted / expected, 2)`; gaps are measured over the trusted readings padded with virtual readings at `assigned_at − i` and `unassigned_at + i`, so a complete stream has `max_gap_min = i` and late starts or early stops count as gaps. | Makes "a gap of exactly 30 min is not a breach" well defined (2 missing readings = 30 min), and catches loggers that start late or stop early. |
| 15 | 2026-11-19 | **Boundaries.** In range is inclusive (`== max_c` passes). Absolute limit, single and cumulative duration, gap, coverage and dwell use strict comparisons (equal to the limit passes). NEAR_LIMIT_UNCERTAIN is inclusive (`abs(t − limit) ≤ u`, after rounding to 2 dp). | Matches the plan's boundary tests (30 min within a 30 min allowance passes; 40 fails; 30 min gap passes). |
| 16 | 2026-11-19 | **POLICY_MISMATCH_DECLARED compares the full `policy_id`** (code and version). (Generator behaviour refined by #26.) | Strict and simple; the planner's declaration is either exactly right or flagged. |

Sequence numbers continue the raw history; `event_at` = logger `unassigned_at`.
